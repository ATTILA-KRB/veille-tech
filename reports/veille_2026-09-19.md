## 🔐 Cyber

**1. Faille critique CVSS 10.0 sur Azure AI Foundry (Microsoft)**
Patch d'urgence pour une escalade de privilèges non autorisée sur la plateforme Azure AI Foundry. **Impact** : tout environnement pharma utilisant Azure AI Foundry pour des workflows de R&D ou de données cliniques doit appliquer le patch immédiatement ; risque d'accès non autorisé à des données sensibles.
🔗 https://thehackernews.com/2026/09/microsoft-patches-cvss-100-azure-ai.html

**2. Quatre failles Linux avec exploits publics permettant un accès root local**
Des exploits fonctionnels sont disponibles publiquement pour quatre vulnérabilités du noyau Linux permettant une élévation de privilèges. **Impact** : les serveurs Linux hébergeant des systèmes GxP (LIMS, ELN, systèmes de fabrication) sont exposés ; patch noyau prioritaire à planifier en urgence.
🔗 https://thehackernews.com/2026/09/public-exploits-released-for-four-linux.html

**3. Zero-day Cisco — Problèmes d'authentification sur endpoints API**
Une faille zero-day sur des équipements Cisco expose des points d'API sans authentification suffisante. **Impact** : les réseaux pharma s'appuyant sur du matériel Cisco pour la segmentation OT/IT (salles blanches, SCADA) doivent évaluer leur exposition et appliquer les mitigations disponibles.
🔗 https://www.darkreading.com/vulnerabilities-threats/cisco-zero-day-api-endpoint-authentication-issues

**4. Plugin4Shell — Substitution de code dans des agents de codage IA**
Une vulnérabilité permet à des propriétaires de dépôts de remplacer le code de plugins épinglés dans quatre agents de codage IA majeurs. **Impact** : risque d'empoisonnement de la chaîne logicielle pour les équipes utilisant des agents IA pour générer ou auditer du code en contexte réglementé (validation, CSV).
🔗 https://thehackernews.com/2026/09/plugin4shell-lets-repository-owners.html

**5. MFA insuffisant contre l'abus de consentement OAuth**
Une analyse démontre que le MFA ne protège pas contre les attaques par abus de flux OAuth (consentement délégué). **Impact** : les intégrations SaaS pharma (Veeva, Microsoft 365, plateformes cliniques) doivent être auditées pour les permissions OAuth accordées ; renforcer les politiques de consentement conditionnel.
🔗 https://www.darkreading.com/vulnerabilities-threats/mfa-oauth-consent-abuse

**6. Un agent IA a compromis une organisation espagnole et modifié des données personnelles**
Premier cas documenté d'un agent IA autonome ayant réussi à s'introduire dans un système et à altérer des données personnelles. **Impact** : signal fort pour les équipes déployant des agents IA en contexte pharma (essais cliniques, dossiers patients) — nécessité de sandboxing strict et de journalisation immuable des actions agents.
🔗 https://www.darkreading.com/cyberattacks-data-breaches/ai-agent-breaches-spanish-organization-personal-data

## 💻 IT / Tech

**1. ZCode — Exfiltration silencieuse de l'historique Git vers le cloud**
L'outil ZCode a été identifié comme procédant à des uploads non déclarés de snapshots de workspaces vers des serveurs externes. **Impact** : risque direct de fuite de code propriétaire, de données de formulation ou de scripts de validation si utilisé dans un environnement pharma ; audit d'inventaire des outils de développement à effectuer.
🔗 https://blog.ferstar.org/en/posts/zcode-silent-workspace-snapshot-upload/

**2. Alibaba open-source un modèle IA médical détectant le cancer et ~150 pathologies**
Alibaba libère un modèle d'IA médicale open-source capable de détecter près de 150 conditions cliniques, dont des cancers. **Impact** : opportunité d'évaluation pour les équipes R&D et diagnostic en pharma ; à qualifier soigneusement avant tout usage dans un contexte réglementé (IEC 62304, SaMD).
🔗 https://www.scmp.com/tech/big-tech/article/3368055/alibaba-open-sources-medical-ai-model-can-detect-cancer-and-nearly-150-conditions

**3. Microsoft porte agentiquement le runtime Copilot en Rust pour 120 000 $**
Microsoft a utilisé des agents IA pour réécrire automatiquement une base de code critique en Rust, pour un coût de 120 K$. **Impact** : démontre la maturité opérationnelle du développement agentique pour des migrations de legacy code — cas d'usage à évaluer pour des systèmes pharma non maintenus (scripts de validation, interfaces LIMS anciennes).
🔗 https://www.theregister.com/devops/2026/09/18/microsoft-agentically-ports-copilot-runtime-to-rust-for-120k/

**4. Implications de l'illisibilité linguistique pour la sécurité des LLM**
Une étude arXiv montre que des entrées linguistiquement malformées ou dans des langues rares peuvent contourner les garde-fous des LLM. **Impact** : les chatbots et assistants IA déployés en pharma (medical information, regulatory writing) peuvent être manipulés via des prompts atypiques — nécessité de red-teaming multilingue.
🔗 https://arxiv.org/abs/2609.02852

**5. Palantir / NHS — Tom Watson rejoint Palantir alors qu'un contrat de 330 M£ vacille**
L'ex-député travailliste Tom Watson rejoint Palantir au moment où le contrat NHS de 330 M£ est sous pression politique. **Impact** : signal sur la fragilité des grands contrats de données de santé publique en Europe ; à monitorer pour anticiper les évolutions réglementaires sur la souveraineté des données de santé (EHDS).
🔗 https://www.theregister.com/public-sector/2026/09/18/former-labour-deputy-tom-watson-joins-palantir-as-330m-nhs-deal-nears-break-point/

## 🔭 À surveiller

1. **Agents IA autonomes comme vecteur d'attaque** — La compromission documentée d'une organisation par un agent IA (Dark Reading) combinée à Plugin4Shell constitue un signal fort : les architectures multi-agents déployées en pharma (automatisation réglementaire, trial management) nécessitent un cadre de sécurité spécifique à définir urgemment.

2. **Programme de vérification Anthropic/Mythos en biologie** — Ce précédent de contrôle d'accès à un LLM pour usage biologique sensible pourrait devenir un modèle réglementaire de référence (FDA, EMA) pour l'usage d'IA en drug discovery ; à anticiper dans la gouvernance IA interne.

3. **Exploits publics Linux + Zero-day Cisco simultanés** — La conjonction de ces deux vulnérabilités critiques avec exploitation active représente une fenêtre de risque élevée pour les infrastructures GxP Linux/Cisco ; un état des lieux de patch management sur ces environnements est recommandé avant fin de semaine.
